There are two flows. DOC labels the form-post flow "legacy" and says: "For new integrations, use the host-to-host checkout flow" (DOC web-payments, top banner).

## 4. Signatures

### 4.1 Request signature (create, query, refund, e-wallet, soundbox)

`sha512( UPPER( key;CID;cartid;AMT;currency ) )`, output as **lowercase hex**.
- `AMT` = the amount formatted to 2 decimals with commas and the decimal point removed: `100.00`→`10000`, `1`→`100`, `0.1`→`010`. **The leading zero is kept** (DOC v2/web-payments#web-payments-create-checkout-session; WOO L378-382 implements it as `str_replace('.', '', number_format(x, 2, '.', ''))`).
- The whole string, **including the key, is uppercased before hashing** (DOC same; WOO L263-269).
- Pre-auth adds `;v_preauth` at the end (DOC v2/preauth-and-capture#preauth-and-capture-create-checkout-session).

### 4.2 Callback, return and checkout-response signature

`sha512( UPPER( key;CID;POID;cartid;AMT;currency;status ) )`, compared as lowercase hex. DOC v2/web-payments#web-payments-handle-server-callback; WOO L398-412 (uses `hash_equals` and lowercases the received value).
- DOC names the fields `v_cartid, v_amount, v_currency`, but in a callback they arrive as `cartid`, `amount`, `currency`. Use the posted values.
- `status` is the full text, e.g. `88 - Transferred` → `88 - TRANSFERRED`.

### 4.3 Terminal and Soundbox APIs use a DIFFERENT convention

The string is **not** uppercased, and the **hex output is uppercase**. For example, RemotePay hashes `key;AMT;currency;ReferenceNo;TerminalId` with the reference left in lower case (DOC terminal-payments#terminal-payments-request: "Hash the resultant string with SHA512. Convert the resultant string to uppercase").

## 10. Not confirmed by any official material

Payment expiry/timeout · gateway minimum amount · `v_cartid` max length · behaviour on a duplicate `v_cartid` · callback retry schedule · callback source IPs · timezone of `refunddate` · any paid-time field · partial-refund semantics · cancel/void of online payments · rate limits.

## Independent review notes (23 Oct 2026)

The signature upper-cases its whole string, so the CASE of `cartid` is not signed: references are restricted to upper case (`[A-Z0-9._-]`), and a callback whose cartid has lower-case letters is not ours (fixed 23 Oct 2026 after review).
