# Billplz

## Use the bayarkit adapter

Install `@bayarkit/core` and `@bayarkit/billplz`. Evidence: **written from the official docs, not yet measured on the sandbox**.

```ts
import { checkoutResponse, confirmPayment, readCallback } from '@bayarkit/core'
import { billplz } from '@bayarkit/billplz'

const gateway = billplz({ secretKey, xSignatureKey, collectionId, environment: 'sandbox' })
const payment = await gateway.createPayment({ reference, amount /* sen */, description, customer, returnUrl, callbackUrl })
return checkoutResponse(payment) // a 303 redirect, or a self-submitting page when the gateway wants a POST form
// then, in the callback route:
const result = await confirmPayment(gateway, await readCallback(request), { reference, amount })
```

Test without real money: `startFakeBillplz` from `@bayarkit/testing`.

The full contract with a source for every fact: `gateways/billplz/spec.md` in the bayarkit repository.

## Billplz traps (each from an official source or a sandbox measurement)

- X Signature sorts the concatenated `key+value` strings, not the keys: the docs' "sort keys" wording gives a different HMAC than the official plugin and test vectors. *(support.billplz.com/api X Signature steps; official WooCommerce plugin L336–341)*
- Answer the callback with HTTP 200 within 20 s or Billplz retries (up to 5 attempts over ~24 h), and callback and redirect arrive in no fixed order. *(support.billplz.com/api callback retry schedule)*
- A deleted bill comes back if the customer completes a payment already in flight, so `paid=true` can arrive after DELETE. *(support.billplz.com/api delete bill)*

## Rules that apply to every Malaysian gateway

1. Amounts are integer sen. Never compare floating-point ringgit.
2. Never mark an order paid from the return URL or the callback body alone: verify the signature, ask the gateway again,
   then match reference, amount and currency exactly (`confirmPayment` does all three).
3. Gateways retry callbacks: marking an order paid must be idempotent.
4. Use one reference per payment attempt, so a late callback from an old attempt cannot match a new one.
5. Errors and logs never contain keys or secrets.
