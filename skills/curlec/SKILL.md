# Razorpay Curlec

## Use the bayarkit adapter

Install `@bayarkit/core` and `@bayarkit/curlec`. Evidence: **written from the official docs, not yet measured on the sandbox**.

```ts
import { checkoutResponse, confirmPayment, readCallback } from '@bayarkit/core'
import { curlec } from '@bayarkit/curlec'

const gateway = curlec({ keyId, keySecret, webhookSecret })
const payment = await gateway.createPayment({ reference, amount /* sen */, description, customer, returnUrl, callbackUrl })
return checkoutResponse(payment) // a 303 redirect, or a self-submitting page when the gateway wants a POST form
// then, in the callback route:
const result = await confirmPayment(gateway, await readCallback(request), { reference, amount })
```

Test without real money: `startFakeCurlec` from `@bayarkit/testing`.

The full contract with a source for every fact: `gateways/curlec/spec.md` in the bayarkit repository.

## Razorpay Curlec traps (each from an official source or a sandbox measurement)

- The official Node webhook sample verifies JSON.stringify(parsedBody), but the signature is HMAC-SHA256 over the RAW body bytes, so re-serialising breaks verification. *(https://curlec.com/docs/webhooks/validate-test.md L134 vs L155-159)*
- Webhooks are signed with the Dashboard webhook secret, while the checkout/callback razorpay_signature is HMAC-SHA256(order_id|payment_id) keyed with the API key secret, and order_id must be your stored one, not the posted one. *(https://curlec.com/docs/webhooks/setup-edit-payments.md L44-45; checkout integration-steps.md L624-640)*
- An authorized payment that is not captured within 3 days is auto-refunded, and auto-capture applies only to payments created through the Orders API. *(https://curlec.com/docs/payments/payments/capture-settings.md L24, L37)*
- Docs say a failed attempt needs a NEW order and that receipt must be unique, yet the official WooCommerce plugin reuses the order and repeats the receipt, so test retry behaviour yourself. *(https://curlec.com/docs/api/orders/create.md L19-21, L359-365 vs razorpay-woocommerce woo-razorpay.php L1188-1210, L1569)*

## Rules that apply to every Malaysian gateway

1. Amounts are integer sen. Never compare floating-point ringgit.
2. Never mark an order paid from the return URL or the callback body alone: verify the signature, ask the gateway again,
   then match reference, amount and currency exactly (`confirmPayment` does all three).
3. Gateways retry callbacks, and two customers can pay at once: mark an order paid in one transaction that locks the
   order row, with a unique index on the gateway's payment id, and retry on deadlock (README, "After confirmPayment").
4. Use one reference per payment attempt, so a late callback from an old attempt cannot match a new one.
5. Errors and logs never contain keys or secrets.
6. Save the environment and a fingerprint of the key that created each payment, verify its callback with those
   credentials, and keep an old key configured until its last bill expires.
