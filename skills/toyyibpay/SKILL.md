# toyyibPay

## Use the bayarkit adapter

Install `@bayarkit/core` and `@bayarkit/toyyibpay`. Evidence: **measured on the toyyibPay sandbox**.

```ts
import { checkoutResponse, confirmPayment, readCallback } from '@bayarkit/core'
import { toyyibpay } from '@bayarkit/toyyibpay'

const gateway = toyyibpay({ secretKey, categoryCode, environment: 'sandbox' })
const payment = await gateway.createPayment({ reference, amount /* sen */, description, customer, returnUrl, callbackUrl })
return checkoutResponse(payment) // a 303 redirect, or a self-submitting page when the gateway wants a POST form
// then, in the callback route:
const result = await confirmPayment(gateway, await readCallback(request), { reference, amount })
```

Test without real money: `startFakeToyyibPay` from `@bayarkit/testing`.

The full contract with a source for every fact: `gateways/toyyibpay/spec.md` in the bayarkit repository.

## toyyibPay traps (each from an official source or a sandbox measurement)

- A secret key from another account (or a typo) makes `getBillTransactions` answer `No data found!`, the same text as an unpaid bill: a wrong key shows up as payments that never confirm, not as an error. *(gateways/toyyibpay/spec.md (measured))*
- A bill with no transactions answers the text `No data found!`, not `[]`: a strict JSON parser reports every unpaid bill as an error. *(gateways/toyyibpay/spec.md (measured))*
- Callbacks arrive as `multipart/form-data`; code that only parses URL-encoded bodies sees no fields. *(gateways/toyyibpay/spec.md (measured))*
- `billExpiryDate` is read in Malaysia time, and RM1.00 (100 sen) itself is accepted although the docs say "more than RM1.00". *(gateways/toyyibpay/spec.md (measured))*

## Rules that apply to every Malaysian gateway

1. Amounts are integer sen. Never compare floating-point ringgit.
2. Never mark an order paid from the return URL or the callback body alone: verify the signature, ask the gateway again,
   then match reference, amount and currency exactly (`confirmPayment` does all three).
3. Gateways retry callbacks: marking an order paid must be idempotent.
4. Use one reference per payment attempt, so a late callback from an old attempt cannot match a new one.
5. Errors and logs never contain keys or secrets.
