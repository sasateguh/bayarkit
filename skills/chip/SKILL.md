# CHIP

## Use the bayarkit adapter

Install `@bayarkit/core` and `@bayarkit/chip`. Evidence: **written from the official docs, not yet measured on the sandbox**.

```ts
import { checkoutResponse, confirmPayment, readCallback } from '@bayarkit/core'
import { chip } from '@bayarkit/chip'

const gateway = chip({ secretKey, brandId, publicKey, environment: 'test' })
const payment = await gateway.createPayment({ reference, amount /* sen */, description, customer, returnUrl, callbackUrl })
return checkoutResponse(payment) // a 303 redirect, or a self-submitting page when the gateway wants a POST form
// then, in the callback route:
const result = await confirmPayment(gateway, await readCallback(request), { reference, amount })
```

Test without real money: `startFakeChip` from `@bayarkit/testing`.

The full contract with a source for every fact: `gateways/chip/spec.md` in the bayarkit repository.

## CHIP traps (each from an official source or a sandbox measurement)

- Callbacks are signed in the `X-Signature` header: base64 RSA PKCS#1 v1.5 SHA-256 over the RAW body. `GET /public_key/` returns a JSON-quoted PEM string that must be JSON-decoded first. *(CHIP Collect OpenAPI L895–917; docs /overview/callbacks)*
- CHIP's own AI skill lists fields and a status that do not exist (`failure_callback`, `cancel_callback`, status `failed`) and a wrapped payload; the OpenAPI spec has none of these. There is no `failed` status: paid means `paid`, `cleared` or `settled`. *(CHIP Collect OpenAPI status enum vs github.com/CHIPAsia/skill SKILL.md)*
- `success_callback` must not contain a port, not even `:443`; redirect and callback fields go at the top level of the create body (nested inside `purchase` they are ignored). *(CHIP Collect OpenAPI L2953–2975; docs /overview/callbacks)*

## Rules that apply to every Malaysian gateway

1. Amounts are integer sen. Never compare floating-point ringgit.
2. Never mark an order paid from the return URL or the callback body alone: verify the signature, ask the gateway again,
   then match reference, amount and currency exactly (`confirmPayment` does all three).
3. Gateways retry callbacks: marking an order paid must be idempotent.
4. Use one reference per payment attempt, so a late callback from an old attempt cannot match a new one.
5. Errors and logs never contain keys or secrets.
